# STRIPE 동작 흐름 — 학생이 들어와서 리포트를 받기까지

최종 갱신 **2026-09-24** · 기준 커밋 `a5cf174`

`docs/현재상태.md` 가 "무엇이 있나"라면, 이 문서는 **"그게 실제로 어떻게 맞물려 도나"** 다.
화면 코드에서 실제로 호출하는 API를 따라가 썼다. 문서와 실제가 어긋나지 않는다.

---

## 0. 전체 그림

```
학생 로그인
   ↓
[설문]     9문항 + 조건부 2문항          →  프로필 생성 · 세션 생성
   ↓
[읽기]     지문을 눈으로 읽고 버튼          →  A4(음절/초) 산출
   ↓
[문제]     6문항 객관식                   →  문항별 즉시 채점
   ↓
   회차 집계 → Betts 판정 → 적응형 결정
   ↓                          ↓
  계속(2회차)                 종료
   └──── 읽기로 되돌아감        ↓
                          [판정] 유창성 × 독해 → 9칸 → G1~G6
                              ↓
                          [처방] 난도 범위 · 지문 추천 · 약점 훈련
                              ↓
                          [리포트] 3층 구조 + 면책 문구
                              ↓
                          결과 화면
```

**한 세션은 최대 2회차다**(`adaptive.py:21` `MAX_ROUNDS = 2`).
한 회차 = 지문 1편 읽기 + 문항 6개.

## 1. 설문 — 진단의 시작점

**화면** `DiagnosisView.vue` `phase = 'survey'`

진입하자마자 두 가지를 한다(`DiagnosisView.vue:697`).

```
checkResume()       GET  /api/diagnosis/my/summary      중단된 세션이 있나?
loadDefinition()    GET  /api/diagnosis/survey/definition  문항을 받아온다
```

**문항은 화면에 없다.** 서버의 `survey_questions.json` 을 받아 렌더링만 한다.
문구가 바뀌어도 프론트를 다시 빌드하지 않는다.

**중단된 세션이 있으면** `phase = 'resume-choice'` 로 가서 "이어하기 / 새로 시작"을
묻는다. 새로 시작을 고르면 `POST /session/{id}/abandon` 으로 이전 세션을 버린다.

### 제출할 때 일어나는 일

`submitSurvey()` — **API 3개를 연달아 부른다**(`DiagnosisView.vue:378`).

```
POST /api/diagnosis/profile            프로필 생성 → profile_id
POST /api/diagnosis/session            세션 생성 (silent_mode: true) → session_id
POST /api/diagnosis/session/{id}/start 1회차 시작 → round_id
```

**화면에 뜨지 않은 문항은 보내지 않는다.** 조건부 문항(A-5·A-6)은 비독자로 판정된
학생에게만 노출되는데, 안 뜬 문항의 응답이 저장되면 분석 표본이 오염된다.
**서버도 문항 유형을 다시 확인해 걸러낸다** — 화면만 믿지 않는다.

**이 흐름은 재시도를 걸지 않는다.** 프로필·세션을 생성하므로 그대로 다시 부르면
중복 행이 쌓인다. 설문 단계라 잃을 응답도 없어 처음부터 다시가 안전하다.

**`silent_mode: true` 가 고정이다** — MVP1은 전 학년 묵독이다. 음독 경로는 화면에
없다(`현재상태.md` §2-4).

## 2. 읽기 — A4(묵독 자동성) 측정

**화면** `phase = 'reading'` · **지문** `GET /round/{id}/content`

학생이 **'읽기 시작'** 을 누르면 타이머가 돌고, **'다 읽었어'** 를 누르면 멈춘다.
그 간격이 `silent_reading_time` 이다.

### 두 개의 가드가 걸려 있다

**① 화면 쪽 — 너무 빠르면 한 번 되돌린다** (`stopReading()`, `DiagnosisView.vue:525`)

```
음절/초 > MAX_PLAUSIBLE_SPS  그리고 첫 시도라면
   → "너무 빨라요! 글을 끝까지 읽었는지 확인하고 다시 읽어줘 📖"
   → 타이머 리셋, 읽기 단계 유지
```

**두 번째 시도는 그대로 통과시킨다.** 학생 의사를 존중한다 — 화면이 강제로 막지
않는다. 대신 아래 ②가 판정에서 거른다.

**② 서버 쪽 — 판정에서 제외한다** (`judgment.py:28`)

```
A4_PLAUSIBLE_MIN = 0.3 음절/초     200음절 기준 11분 이상 → 이탈·중단
A4_PLAUSIBLE_MAX = 15.0 음절/초    속독 최상위도 넘음 → 미독(건너뛰기)
```

**왜 둘 다 있나** — 화면 가드는 아이에게 다시 읽을 기회를 주는 것이고, 서버 가드는
그래도 이상한 값이 판정에 들어가는 것을 막는 것이다. 화면만 믿으면 API를 직접
호출해 우회할 수 있다.

### 전송

```
POST /api/diagnosis/fluency/silent
     { session_id, round_id, silent_reading_time, away_events }
```

**`away_events` 는 읽는 중 탭 전환 기록이다**(STR-79). 서버가 구간을 짝지어 집계하되
**읽기 시간에서 빼지 않는다** — 얼마를 빼는 게 맞는지는 파일럿이 정할 문제다.

**이 함수만 재시도한다**(`sendSilentReading()`). `stopReading()` 을 다시 부르면
경과 시간이 재계산되어 A4가 오염된다.

## 3. 문제 — 독해 채점

**화면** `phase = 'questions'` · 6문항 객관식

### 고를 때마다 바로 저장한다

```
POST /api/diagnosis/comprehension
     { round_id, question_id, student_answer }
```

**왜 즉시 저장하나** — 중간에 창을 닫아도 답이 남아야 '이어하기'가 의미를 갖는다.
서버가 (회차, 문항) 단위로 갱신하므로 **답을 고쳐 골라도 행이 늘지 않는다.**

**저장 실패는 화면을 막지 않는다.** 실패한 문항 번호를 `unsavedIds` 에 모아두고
제출할 때 다시 보낸다. 그리고 그 목록을 **`localStorage` 에도 남긴다** —
아동은 실수로 새로고침하기 쉽다.

### 제출

`submitAnswers()` 가 못 보낸 문항을 먼저 밀어 넣고, 회차를 닫는다.

```
POST /api/diagnosis/round/{round_id}/complete
```

**답안은 이미 서버에 있으므로 이 단계는 재시도를 건다.** 처음부터 다시 시킬 이유가
없다.

## 4. 회차 집계 → Betts → 적응형 결정

`complete_round()` (`diagnosis.py:796`) 가 세 가지를 순서대로 한다.

### ① 집계 + Betts 판정

```
정답률 ≥ 0.90   independent   독립 수준 — 혼자 읽어도 되는 난도
정답률 ≥ 0.70   instructional 교수 수준 — 도움받으면 읽을 수 있는 난도
그 미만         frustration   좌절 수준 — 너무 어렵다
```
`scoring.py:10`

영역별(A5 사실적 / A6 추론 / A7 비판) 정답률도 함께 낸다.

### ② 지금까지의 Betts 이력을 모은다

### ③ 다음 행동을 정한다 (`adaptive.py:59`)

```
① 2연속 instructional   →  종료 (completed)      신뢰도 normal
② 2연속 frustration     →  종료 (early_stop)     신뢰도 low
③ 최대 회차(2) 도달      →  종료 (폴백)           아래 참조
④ 그 외                 →  계속. 난도·장르를 바꿔 다음 지문
```

**난도 조절** — `independent` 면 한 단계 올리고, `frustration` 이면 내린다.
**장르는 매 회차 교대한다**(서사 ↔ 설명).

**③ 폴백에 대한 메모** (`adaptive.py:5-11`) — 명세는 ③을 "MVP2 전용"으로 두면서
"MVP1은 ①②에서 반드시 판정된다"고 썼는데, **2회차 Betts가 서로 다르면
(예: `[independent, frustration]`) ①②에 걸리지 않아 세션이 끝나지 않는다.**
그 공백을 막으려고 최빈 Betts 기준 폴백을 넣었다. 이 규칙은 기획 확정 대기 중이다.

### 계속이면

사용한 지문을 제외하고 다음 지문을 고른다. **중복 노출 방지**(STR-95)가 여기서
작동한다. 풀이 말라 중복을 감수하면 `text_reissued` 를 돌려주고, 화면이 안내한다.

> "지난번 글은 이미 봤을 수 있어서 새로운 글로 바꿨어요 📖"

## 5. 판정 — 이 진단의 결론이 만들어지는 곳

`POST /session/{id}/finalize` → `pipeline.py:79`

### ① 유창성 (A4 기반)

회차별 A4 값 중 **타당성 범위 안의 것만** 모아 판정한다(§2 ②).

```
G4_G6   ≤ 2.5 → low      ≥ 3.8 → high      그 사이 mid
G7      ≤ 2.8 → low      ≥ 4.2 → high
```

**이 경계값은 잠정이다.** 파일럿 분포가 있어야 실제 P33/P67이 나온다.

### ② 독해

전체 정답률과 **12셀 약점 프로파일**(A5·A6·A7 × 서사·설명)을 낸다.

```
G4_G6   ≤ 0.55 → low     ≥ 0.80 → high
G7      ≤ 0.50 → low     ≥ 0.75 → high
```

### ③ 9칸 매트릭스 → 라벨 + 처방군

`judgment.py:183`

```
                    독해 high      독해 mid       독해 low
유창성 high        excellent       caution        risk
유창성 mid         observe         caution        risk
유창성 low         observe         risk           urgent

                    독해 high      독해 mid       독해 low
유창성 high            G1             G2            G4
유창성 mid             G2             G2            G4
유창성 low             G3             G5            G6
```

**두 표는 용도가 다르다.** `label_5` 는 **사람에게 보여줄 말**(학생 화면의
"보통이야" 등)이고, `G1~G6` 는 **처방을 고르는 키**다. 그래서 같은 칸이라도
라벨과 처방군이 1:1로 대응하지 않는다.

### ④ 메타인지 — 현재 항상 비어 있다

D-2(예측 문항)가 `reserved` 라 입력이 없다. **입력이 없으면 판정하지 않고
`null` 로 둔다**(`b7ad390`). 리포트에서 항목이 빠진다.

### ⑤ 신뢰도 플래그

세션·유창성·독해 중 **가장 나쁜 값**을 택한다. 중복 지문이 나왔으면 한 단계 더
낮추고 `text_repeated` 사유를 남긴다.

## 6. 처방

`pipeline.py:151`

```
처방군(G1~G6) + 영점 난도
   ↓
① 난도 범위 계산         difficulty_range(group, anchor)
② 지문 추천             3단 승인된 것 중에서, 관심 주제·장르 반영
③ 약점 훈련 방향         12셀에서 정답률 0.70 미만 셀 → 계층적 우선순위
④ 처방 유형 + 톤         A단독 / B단독 / A+B / 기초개입 · 톤 5종
```

**환경 조정은 현재 항상 스킵된다** — 경계값(`ENV_PERCENTILES`)이 비어 있다.
스킵 사유를 `no_score`(보호자 미응답) / `no_thresholds`(경계값 미확정)로
구분해 남긴다.

**도서 추천은 빈 목록이 나온다** — `books` 테이블이 비어 있다(STR-108).

## 7. 리포트

`POST /session/{id}/report` → `report.py:109`

### 3층 구조

```
layer1  요약        라벨 · 응원 문구 · 강점 · 추천 지문 미리보기
layer2  더 알아보기  약점 훈련 · 메타인지(현재 비어 있음)
layer3  (상세)
```

학생 화면(`ResultView.vue`)은 `layer1.encouragement` · `layer1.label` ·
`layer1.strengths` · `layer2.weakness_training` 을 쓴다.

### 응원 문구는 3축으로 고른다

판정(`label_5`) × 처방군 × 독자유형. **이 세 축이 다 필요한 이유**(STR-96) —
위기 판정을 받은 학생이 애독자라는 이유로 *"더 어려운 책에도 도전해보자"* 를
받는 결함이 있었다. 파일럿에서 실제 아이에게 나갈 문구였다.

`report_templates` 가 비어 있으면 **코드 내 폴백 문구**를 쓴다. 폴백에서도
난도 방향을 암시하는 표현을 뺐다.

### LLM 다듬기 — 선택적, 안 켜져 있으면 그냥 건너뛴다

```
ANTHROPIC_API_KEY 없음  →  호출 안 함. 템플릿 그대로. llm_polished = false
있음                   →  claude-haiku-4-5, max_tokens 200, 리포트 1건당 1회
```

**보내는 것은 응원 문구 한 줄뿐이다.** 이름·점수·식별자가 가지 않는다.
돌아온 문구에 난도 표현이 섞여 있으면 **버리고 원본을 쓴다** — LLM이 STR-96을
조용히 되돌리는 것을 막는다.

### 면책 문구

항상 `basic` 이 붙는다. 조건에 따라 추가된다.

```
basic                 이 결과는 참고 정보입니다 (항상)
silent_only           묵독 기반으로 수행되었습니다
early_stop            진단 회차가 적어 정확도가 제한적입니다
fluency_unavailable   유창성 측정 데이터가 부족한 잠정 판정입니다
text_repeated         이전에 읽은 지문이 다시 나왔습니다
```

**유창성이 `mid` 로 채워져 있어도 그게 실측이 아닐 수 있다.** 면책 문구가 그
사실을 드러내는 유일한 장치다.

## 9. 보호자 경로 — 별도 흐름

`ParentSurveyView.vue` · `/parent`

```
GET  /api/parent/survey/definition   문항 10개
GET  /api/parent/survey/latest       이미 낸 응답이 있나
POST /api/parent/survey              제출
```

**학생 진단과 시점이 분리돼 있다.** 보호자가 언제 응답하든 상관없다.
수집한 가정환경 4문항(B-3~B-6)이 환경 조정 처방의 입력이 되는데, 현재는 경계값이
없어 판정까지 가지 않는다.

**보호자 설문은 선택이다.** 미응답·부분응답이 정상 케이스이며, 가정 독서 환경
수준은 **4문항 전건 응답 시에만** 산출된다.

## 10. 중간에 끊겼을 때

이 서비스는 **초4~중1 아동**이 쓴다. 새로고침·창 닫기·네트워크 끊김이 일상적이다.

| 어디서 끊기나 | 무엇이 남나 | 어떻게 복구하나 |
|---|---|---|
| 설문 중 | 아무것도 안 남음 | 처음부터. 잃을 게 없다 |
| 읽기 중 | 세션·회차 | 이어하기 → 그 회차 지문부터 |
| 문제 푸는 중 | **고른 답까지** | 이어하기 → 답이 되살아남 |
| 저장 실패분 | `localStorage` 백업 | 재진입 시 복원 |
| 판정·리포트 실패 | 전부 | **재시도 버튼만 누르면 됨** |

**마지막 줄이 중요하다.** 문항을 다 풀고 판정만 실패한 상태에서 처음부터 다시
시키면, 25분 응시한 아이에게 그걸 또 시키는 것이 된다. 그래서 `finalize()` 는
재시도를 건다.

**401(토큰 만료)은 다르게 다룬다** — 인터셉터가 로그인 화면으로 보낸다.
재시도해도 의미가 없기 때문이다.

`현재상태.md` §3의 네 원칙이 실제로 어디에 박혀 있는지.
