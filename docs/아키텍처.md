# STRIPE 아키텍처

작성 2026-08-09 · 코드 실측 기준

읽기 능력 진단·처방 서비스. 초4~중1 학생이 지문을 읽고 문항에 답하면,
읽기 수준을 판정하고 그 수준에 맞는 책을 제안한다.

> **제품 목적** — 순위를 매기는 것이 아니라, *"이 정도 수준이면 이런 책을
> 읽으면 좋겠다"* 를 알려주는 것. 이 문장이 여러 설계 판단의 기준이 됐다.

## 2. 백엔드

### 2-1. 계층

```
app/api/endpoints/     HTTP 경계 — 인증·권한·검증·직렬화
        ↓
app/services/          도메인 로직 — 순수 함수 위주, DB 를 모른다
        ↓
app/models/            SQLAlchemy 모델 (21개 테이블)
```

**서비스 계층을 순수하게 유지한 것이 테스트 밀도의 근거다.** 판정·처방
엔진은 DB 없이 단위 테스트가 돌고, DB 가 필요한 것만 통합 테스트로 뺐다.

## 3. 진단 흐름

```
설문 (9 + 조건부 2)
   │  독자유형 1차(A-2·A-3) → 비독자면 A-5·A-6 추가 노출
   │  독자유형 2차(A-4 생애 그래프) → 급락/하락/고정형
   ▼
세션 생성 → 1회차
   │
   ├─ 지문 읽기 (묵독)        → A4 자동성 (음절/초)
   └─ 문항 응답 (A5·A6·A7)   → 영역별 정답률 · Betts
   │
   ▼
적응형 판단 ── continue ──▶ 2회차 (난도 조절 · 장르 교대)
   │  stop
   ▼
판정 (§3)
   유창성 3단 × 독해 3단 → 9셀 → label_5 + 처방군 G1~G6
   │
   ▼
처방 (§5)
   난도 범위 · 약점 훈련 계획 · 톤 · 환경 조정
   │
   ▼
리포트 (3층) · 적합도서 추천
```

### 측정 타당도 장치

이 프로젝트에서 반복해 드러난 문제는 **"과제를 수행하지 않고도 통과하는
측정"** 이었다. 발견될 때마다 방어를 넣었다.

| 장치 | 막는 것 | 발견 경위 |
|---|---|---|
| 정답 위치 균형 | "1번 찍기" 정답률 0.698 → 0.267 | PM 이 직접 응시 |
| 선지 길이 균형 | "최장 선지 찍기" 0.742 → 0.250 | PM 이 직접 응시 |
| A4 타당성 게이트 | 미독·이탈이 정상 판정으로 섞임 | 코드 검토 |
| 음독 정렬 채점 | 다른 말을 읽어도 정확도 1.000 | 음독 전수조사 |
| 문항 품질 검사 | 위 두 편향의 재발 | 자동화 |

**전부 "겉보기엔 정상"이었다.** 그래서 자동 검사로 고정해 두었다.

## 4. 데이터 모델 (21 테이블)

```
users ─┬─ user_relations (보호자-학생)
       ├─ consent_records          동의 회수 (서면/전자)
       └─ student_profiles ─┬─ parent_responses      보호자 설문
                            └─ diagnosis_sessions
                                  └─ diagnosis_rounds
                                        ├─ question_responses
                                        ├─ comprehension_results
                                        └─ fluency_results   묵독·음독 통합
                                  └─ judgment_results
                                        └─ prescription_results
                                        └─ reports

texts ─ item_sets ─ questions        진단 콘텐츠
books                                 적합도서 카탈로그
report_templates                      리포트 문구 (조건 3축)
content_reviews                       검수 이력
data_disposal_logs · deletion_requests  파기·삭제요청 (FK 없음 — 증적 보존)
```

**설계 판단 두 가지**

- **`fluency_results` 하나로 묵독·음독을 통합**했다(`type` 컬럼). 명세는
  `oral_reading_results` / `silent_reading_results` 를 나누지만, 공유 컬럼이
  대부분이라 합쳤다. 기획 명세와의 차이로 보고해 두었다.
- **파기·삭제요청 기록에는 FK 를 걸지 않았다.** FK 가 있으면 파기와 동시에
  기록도 지워져 증적이 남지 않는다.

### 설문이 화면에 박혀 있지 않다

```
backend/app/data/survey_questions.json   ← 정본 (37문항)
        │
        ├─ GET /api/diagnosis/survey/definition ──▶ 학생 화면이 렌더링만
        ├─ GET /api/parent/survey/definition    ──▶ 보호자 화면
        └─ 서버 검증도 같은 파일을 참조
```

문구가 잠정본이라 계속 바뀐다. 화면에 박으면 문구 한 줄에 프론트를 다시
빌드해야 하고, **서버 검증 규칙과 화면 선지가 따로 놀 여지**가 생긴다.

**모든 선지가 자기 저장값을 직접 들고 있다.** 순서로 값을 매기면 선지를 한
번만 재배열해도 저장 데이터가 어긋난다. 특히 척도 문항은 표시 순서(많이 읽음
→ 적게 읽음)와 값의 방향(클수록 많이 읽음)이 반대라, 순서로 매기면 **가장
많이 읽는 학생이 비독자로 분류된다.**

## 6. 관통하는 설계 원칙

### 6-1. 기획이 바꿀 수 있는 것은 코드 밖에 둔다

| 대상 | 위치 | 바뀔 때 |
|---|---|---|
| 설문 문항·선지 | `survey_questions.json` | 파일만 교체 |
| 리포트 문구 | `report_templates` 테이블 | 행만 교체 |
| 환경 경계값 P33/P67 | `ENV_PERCENTILES` 설정값 | 표만 채움 |
| 판정 임계값 | `judgment.py` 상수 | 값만 교체 |

### 6-2. 값이 없으면 만들지 않는다

파일럿 전이라 확정되지 않은 값이 많다. **임의 기본값을 넣지 않는다.**

- 환경 경계값이 없으면 → **기능을 건너뛴다**. 임시값으로 판정하면 근거 없는
  등급이 진짜 값처럼 저장돼 나중에 구분할 수 없다
- 보호자가 일부만 답하면 → **점수를 내지 않는다**. 3문항 합(3~12)은 4문항
  합(4~16)과 같은 척도가 아니다
- 미응답에 0 을 넣지 않는다 → **'가장 낮음'과 '모름'은 다른 값이다**

### 6-3. 못 잰 것을 잰 것처럼 기록하지 않는다

- 음독 반복·자기교정 → `disfluency_detectable=false`. **0건이 아니라 미측정**
- 유창성 측정 불가 → `fluency_source=unavailable`, 매트릭스를 왜곡하지 않음
- 잠정 임계값 → 결과 화면에 "잠정 기준" 표기 유지

### 6-4. 아동 개인정보를 최소로 다룬다

```
실명 미수집        식별코드(elem5-017)만. 대조표는 시스템 외부
국외이전 없음      서울 리전. LLM 은 고정 문구만 전송
음성 미저장        VAD 처리 후 즉시 폐기 (보관 시 별도 동의 필요)
파기 경로          관리자 실행 + 정보주체 요청 + 증적 보존
```

## 7. 음독 (진행 중)

기획이 방식 확정을 보류한 영역이다. 현재까지:

```
[측정]  소요시간   VAD (silero ONNX, 선택적 의존성)   완료
        오류 수    감독자 입력 경로                    완료
        전사       STT 어댑터                          보류
[산출]  자동성·정확성·품질 게이트                       완료
[저장]  fluency_results + 사람값/자동값 대조 보존       완료
[활용]  판정 반영                                      기획 확정으로 미반영
[화면]  녹음 · 감독자 확인                              미착수
```

**제안한 방향**: STT(알아맞히기)가 아니라 **강제정렬(채점하기)**. 대본을
알고 있으므로 "무슨 말인지"가 아니라 "이 음절을 제대로 읽었는가"만 보면
된다. 승인 대기 중(STR-16).

## 9. 지금 막혀 있는 것

**코드가 아니라 결정이 막고 있다.**

| | 내용 |
|---|---|
| PM 결정 | 개인정보 보호책임자·사업자 정보·공고일·파일럿 기간 등 법정 필수 6건 → 방침 게시·동의서 배포·법률 자문이 전부 여기 걸림 |
| 기획 대기 | 처방 축(STR-111) · GRI 실체(STR-110) · 도서 데이터(STR-108) · 음독 방식(STR-16) |
| 파일럿 설계 | 대상·인원·응시환경 미확정 → 임계값·계정발급·토큰수명이 연쇄 대기 |

**기술적으로는 묵독 진단 1사이클이 끝에서 끝까지 동작한다.**
